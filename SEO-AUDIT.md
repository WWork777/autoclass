# SEO Audit — autoklass42.ru (multi-page release)

Дата аудита: 2025-09-21 (дата в проекте условная, синхронизировать с датой релиза).
Домен: `https://autoklass42.ru`

## 1. Сводка изменений

Старый сайт был одностраничным (`/` + якорные ссылки `#service`, `#instructors`, `#feedback`, `#stocks`, `#contacts`, `#gallery`, плюс отдельная страница `/documents`). Он полностью переведён на многостраничную архитектуру Next.js App Router с server-компонентами по умолчанию и client-компонентами только там, где нужна интерактивность (переключатели, аккордеон, карусели, счётчики).

Единый источник данных — `src/lib/data.js` (SITE, PROGRAMS, INSTRUCTORS, PAYMENTS, PROMOTIONS, REVIEWS, FAQ, GALLERY, JOURNEY, BLOG_POSTS) и `src/lib/seo.js` (`buildMetadata()` — единая точка генерации title/description/canonical/OG). Цена, часы и сроки правятся один раз в `PROGRAMS` и подтягиваются на все страницы (`/`, `/tseny/`, `/obuchenie/*`), которые её используют.

| `/#instructors` | `/instruktory/` (+ якорь `/#instructors` на главной сохранён) | не требуется |
| `/#feedback` | `/otzyvy/` (+ якорь `/#reviews` на главной сохранён) | не требуется |
| `/#stocks` | `/aktsii/` | не требуется |
| `/#contacts` | `/kontakty/` (+ якорь `/#contacts` на главной сохранён) | не требуется |
| `/#gallery` | `/galereya/` (+ якорь `/#gallery` на главной сохранён) | не требуется |
| `/documents` | `/documents/` | добавлен `trailingSlash: true` в `next.config.mjs` — Next отдаёт 308 с `/documents` на `/documents/` автоматически |

Так как исходный сайт не имел отдельных индексируемых URL для секций (только hash-якоря, которые поисковики не индексируют как отдельные страницы), массовых 301-редиректов не требуется. Единственное реальное техническое изменение — включён `trailingSlash: true`, из-за чего Next.js сам делает 308-redirect с версии URL без слэша на версию со слэшем (`/tseny` → `/tseny/`). Это покрывает все новые страницы автоматически.

**Открытый вопрос**: если у старого сайта в Search Console/Яндекс.Вебмастере есть проиндексированные URL, отличные от перечисленных (например, параметры UTM или дубли), их нужно сверить отдельно после деплоя и добавить точечные redirect в `next.config.mjs` → `redirects()`.

## 4. Structured data — обоснование

- **EducationalOrganization** — в `layout.jsx`, на каждой странице (адреса всех филиалов, телефон, email, дата основания). Заменил невалидный тип `DrivingSchool` (такого типа нет в словаре schema.org) на официальный `EducationalOrganization`.
- **Course** — на страницах категорий (`kategoriya-b`, `kategoriya-a`, обе переподготовки) с реальной ценой из `PROGRAMS`. На подстраницах `mkpp/akpp` Course не дублируется — они описывают формат обучения внутри уже описанного курса, а не отдельный продукт, чтобы не плодить почти идентичные Course-сущности.
- **Person** — на каждой странице инструктора: только реально известные поля (имя, стаж как `jobTitle`-контекст в тексте, фото, `worksFor`). Не выдумано ничего сверх исходных данных.
- **Review** — на `/otzyvy/`, по одному узлу на реальный отзыв, **без** `reviewRating`/`AggregateRating` — на старом сайте не было числовых оценок, придумывать их запрещено ТЗ.
- **FAQPage** — только на `/faq/` (канонический хаб всех вопросов). На страницах категорий и подкатегорий вопросы показаны как обычный HTML (`<details>`/аккордеон) **без** повторного FAQPage JSON-LD, чтобы не создавать конкурирующую разметку на нескольких URL одновременно.
- **LocalBusiness** — на `/kontakty/`, с массивом реальных адресов филиалов.
- **BreadcrumbList** — генерируется программно компонентом `Breadcrumbs.jsx` на каждой внутренней странице (кроме главной).
- **Article** — на страницах блога, с `datePublished` и `author` в соответствии с `BLOG_POSTS`.

Ничего не выдумано: рейтингов, лицензий, номеров документов, стажа сверх исходных данных, придуманных отзывов или адресов автодрома в структурированных данных нет.

## 5. Внутренняя перелинковка

Главная → `/obuchenie/`, `/tseny/`, `/instruktory/`, `/otzyvy/`, `/faq/`, `/kontakty/` (шапка) + предметные ссылки из каждой секции лендинга (Programs → категория/цены, Instructors → карточка инструктора, Journey → автодром, Reviews → все отзывы, Gallery → вся галерея, Promotions → акции, Faq → все вопросы).

`/obuchenie/` → 4 карточки категорий → каждая категория → инструкторы (фильтр по КПП), автодром, цены, FAQ по тегу, соседняя категория/подкатегория.

`/obuchenie/kategoriya-b/` ↔ `/obuchenie/kategoriya-b/mkpp/` ↔ `/obuchenie/kategoriya-b/akpp/` — перелинкованы попарно.

Футер — три колонки ссылок (Обучение / Школа / Информация) на каждой странице сайта, плюс `/documents/` и `/privacy/`.

Orphan-страниц нет: каждая страница из sitemap достижима минимум из одного другого места (шапка, футер или контекстная ссылка в контенте).

## 6. Технический SEO — чек-лист

- [x] `sitemap.xml` — программно генерируется (`src/app/sitemap.js`), включает все статические страницы + все `/instruktory/[slug]/` + все `/blog/[slug]/`.
- [x] `robots.txt` — `src/app/robots.js`, `allow: /`, ссылка на sitemap.
- [x] `canonical` — на каждой странице через `buildMetadata()`.
- [x] `404` — кастомная страница `not-found.jsx` с `robots: noindex`.
- [x] `trailingSlash: true` — единый формат URL, автоматический 308 с версии без слэша.
- [x] `lang="ru"` — задан в `layout.jsx`.
- [x] Иерархия заголовков — на каждой странице ровно один `<h1>` (PageHeader/инлайн), `<h2>`/`<h3>` ниже по смыслу; проверено вручную по каждому файлу `page.jsx`.
- [x] `alt` у изображений — заполнены везде (инструкторы — ФИО, галерея — описательный alt, отзывы — имя автора).
- [x] Open Graph — title/description/url/image через `buildMetadata()`, свои для каждой страницы.
- [x] Favicon — добавлен `src/app/icon.png` (взят из исходного логотипа школы), Next.js подхватывает автоматически.
- [x] Manifest — не требуется (сайт не PWA), не создавался, чтобы не плодить лишние индексируемые технические файлы.

## 7. Производительность

- Все новые страницы — server components (нет `"use client"` там, где не нужна интерактивность). Клиентские компоненты остались только там, где были и раньше: `Header`, `Programs`, `Reviews`, `Instructors`, `FaqAccordion`, `Hero`, `Journey`-анимации на главной.
- Изображения — обычные `<img>` с `loading="lazy"` в галереях; на детальных страницах (hero, обложки) без lazy, так как они above the fold.
- Общий JS-бандл не увеличился существенно — новые страницы переиспользуют уже существующие компоненты и Tailwind-классы, новых тяжёлых зависимостей не добавлено.
- **Не проверено инструментально** в этой сессии: реальный Lighthouse/PageSpeed прогон (LCP/CLS/INP в мс). Рекомендация: прогнать `next build && next start` + Lighthouse после деплоя на прод-домен — dev-сервер с Turbopack HMR не отражает реальные метрики.

## 8. Локальное SEO

- Кемерово упоминается в title/H1/description только там, где это естественно (не на каждой странице подряд — например, на `/instruktory/[slug]/` город есть в title, но в теле текста не повторяется навязчиво).
- Адреса и телефоны берутся из `SITE.addresses`/`SITE.phonesFooter` — единственного источника, совпадающего с реальными данными сайта.
- `LocalBusiness` и `EducationalOrganization` содержат все три реальных филиала.

## 9. Известные ограничения и открытые задачи

1. **Favicon** — добавлен из исходного логотипа (`src/app/icon.png`); при желании можно заменить на более качественный SVG-вариант.
2. **Нет числовых рейтингов отзывов** — сознательно не добавлял `AggregateRating`, так как таких данных не было на старом сайте. Если появится реальный рейтинг (например, из Яндекс.Карт/2ГИС), его нужно подключить в `/otzyvy/` и в `LocalBusiness`.
3. **`/documents/` и `/privacy/`** — честные страницы-заглушки со ссылкой «уточните по телефону/почте», так как реальных номеров лицензии и текста политики конфиденциальности в исходных данных не было. Требуют наполнения реальными документами от школы.
4. **Blog** — создано 2 полноценные статьи на основе реальных данных FAQ, чтобы не плодить пустой контент. Дальнейшее наполнение — по мере появления реальных материалов.
5. **Core Web Vitals** — не измерены инструментально в этой сессии (см. раздел 7), только структурно оптимизированы (server components, lazy images).
6. **Старые проиндексированные URL** — если Search Console/Вебмастер покажут реальные проиндексированные адреса помимо `/` и `/documents`, свериться и добавить точечные redirect.

## 10. Итог

Сайт переведён с одной страницы на 27 маршрутов (statically generated: 19 статических + 8 инструкторов + 2 статьи блога = фактически больше — см. `sitemap.js`), с уникальными title/description/H1/canonical на каждой странице, программной генерацией BreadcrumbList и релевантных Schema.org-типов, единым источником данных для цен/инструкторов/FAQ и без единого выдуманного факта сверх того, что было на исходном сайте.
